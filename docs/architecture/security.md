# 安全基线

## 1. 威胁模型

| 资产 | 攻击者 | 主要威胁 |
|---|---|---|
| 用户密码 | 外部攻击者 | 撞库、拖库 |
| 订阅 token | 外部攻击者 | 撞库/枚举 → 白嫖代理流量 |
| 节点 secret | 攻击者 | 伪造节点 → 劫持配置/流量 |
| 管理员会话 | 外部攻击者 | 提权 → 接管全站 |
| 支付回调 | 外部攻击者 | 伪造支付成功 → 白嫖 |
| 插件 | 恶意插件作者 | 越权读写数据、拖垮面板 |
| 数据库 | 攻击者/内部 | 拖库、SQL 注入 |

## 2. 认证

| 项 | 措施 |
|---|---|
| 密码存储 | Argon2id（`@node-rs/argon2`，无 node-gyp 依赖）；参数 m=64MB, t=3, p=1 |
| 密码策略 | 最小 8 位；禁用常见弱密码库；登录失败不提示"邮箱不存在" |
| 2FA | 管理员强制开启（可配），TOTP；密钥 AES-GCM 加密存储；提供恢复码（一次性） |
| 会话 | 自建会话：随机会话 id 存 cookie（HttpOnly + Secure + SameSite=Lax），`sessions` 表存哈希；空闲 2h / 绝对 7d 过期；IP/UA 异常检测 |
| 强制下线 | 会话存库，管理员可踢下线 |
| CSRF | cookie 用 SameSite=Lax；写操作校验 `Origin`（同源才放行），不使用 GET 触发变更 |
| API Token | 仅存 hash；创建时明文展示一次；可设 scope / 过期；支持吊销 |
| 节点认证 | 每节点独立 secret + HMAC 签名 + 时间窗 + nonce 防重放；支持密钥轮换（双密钥过渡） |
| 插件认证 | 每插件独立 token，可吊销；权限点最小化 |

## 3. 授权

- 后端每个管理接口声明权限点（`requirePermission('admin:node:write')`），**默认拒绝**
- 权限点定义在 `packages/contracts`，前端菜单与后端校验共用，避免"前端隐藏了但接口还能调"
- 越权访问返回 403 且记录审计日志
- 对象级权限：用户只能访问自己的订阅/订单；订阅可见节点组由节点组 ACL 决定

## 4. 输入与输出

| 位置 | 措施 |
|---|---|
| 所有 API 入参 | zod schema 校验（`packages/contracts`），校验失败 422 + 字段级错误 |
| SQL | Drizzle 参数化查询；禁止拼接 SQL；报表用 CTE 模板化 |
| 文件上传（证书/插件包） | 类型白名单、大小限制、zip slip 防护、解压后大小限制、禁止可执行权限、病毒扫描（P2） |
| 订阅输出 | 不回显任何内部 ID；token 使用 uuid v4，足够随机 |
| XSS | React 默认转义；禁止 `dangerouslySetInnerHTML`（除非内容来自受控的 markdown 渲染器 + DOMPurify）；CSP 不放开 `unsafe-inline` |
| SSRF | 插件 git URL / 索引源拉取需校验：只允许 https，解析后禁止内网、回环与云元数据地址段（如 `169.254.169.254`） |

## 5. 密钥管理

| 密钥 | 存储 |
|---|---|
| `MASTER_KEY` | 环境变量，用于加密节点私钥、插件密钥、2FA 密钥 |
| 节点 secret | 数据库加密存储（AES-256-GCM），接口返回脱敏 |
| 支付网关密钥 | 插件配置加密存储 |
| 证书私钥 | 数据库加密存储 |

加密实现：`lib/crypto.ts`，AES-256-GCM，密钥版本号前缀（`v1:...`）以支持轮换。轮换流程：双密钥并存 → 重加密后台任务 → 移除旧密钥。

## 6. 传输安全

- 全站 HTTPS，HSTS（`max-age=31536000; includeSubDomains`）
- 反向代理（Nginx/Caddy）负责 TLS 终结，面板只监听内网
- Agent 支持自签 CA（`tls.ca_file`）、SNI 固定、可关闭证书校验（仅调试）
- 安全响应头（CSP、`X-Content-Type-Options`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy`）

## 7. 支付安全

| 措施 | 说明 |
|---|---|
| 验签 | 网关插件实现对应签名算法，面板不信任任何回调字段直到验签通过 |
| 幂等 | 以 `trade_no` + `gateway` 唯一约束，重复回调不重复开通订阅 |
| 金额校验 | 回调金额必须与订单金额一致，否则进人工复核 |
| 主动查单 | 支付后主动向网关查询确认（可选，防伪造回调） |
| 状态机 | 订单仅允许 `pending → paid → (refunded)`，非法跃迁拒绝并告警 |

## 8. 插件安全

社区插件从 git URL 装进来，等价于"运维主动引入一段不可信代码"。边界靠下面几条保证：

- **默认外置进程**，文件系统只读（可写目录仅 `data/plugins/{key}/data`），低权限用户运行
- **权限点最小化**：manifest 申请 → 管理员逐条确认 → token scope = `granted_scopes`，运行期只能降不能升
- **出网白名单**：只允许 manifest `egress` 里的域名，内网段一律拦截（防 SSRF 与横向移动）
- **前端不注入**：插件 UI 只有 `schema`（核心渲染）与 `iframe`（`sandbox="allow-scripts allow-forms"` + 短时 token）；禁止把插件 bundle 打进主应用
- **git 协议限制**：只允许 https 与公网主机；拒绝 `ssh://`、`file://`、`ext::`
- **不可信构建**：默认 `ALLOW_PLUGIN_BUILD=0`，不在面板上执行 `npm install` / `postinstall`
- **签名**：有 ed25519 签名显示"已验证"；无签名标"未签名社区插件"，安装需二次确认
- **可用性**：单次调用 3s 超时 + 熔断；10 分钟崩溃 5 次自动禁用
- 插件行为全部记入 `plugin_events` 与 `audit_logs`；每次安装/升级/回滚记录 `repo_url@commit_sha`

## 9. 速率限制

见 [api-design §7](api-design.md#7-限流)。除接口级限流外，登录失败锁定、注册频率限制、订阅抓取频率限制是重点。

## 10. 审计

记录范围：登录/登出、用户资料与权限变更、订单状态变更、订阅配额变更、节点增删改与配置下发、插件安装/配置/启停、设置变更、密钥轮换。

审计日志不可篡改（只追加），按月分区，保留 12 个月。日志中不记录明文密码、token、密钥（自动脱敏）。

## 11. 备份与恢复

| 对象 | 策略 |
|---|---|
| PostgreSQL | 每日全量 + WAL 归档（PITR），保留 30 天；备份文件加密 |
| 进程内存 | 缓存 / 计数器丢失可重建；Agent 会重发流量增量（seq 幂等） |
| 配置文件 | 随代码走 git |
| 证书与私钥 | 随 DB 备份 |

恢复演练：至少每季度一次，在干净环境恢复 DB → 启动面板 → 验证登录/订阅/节点。

## 12. 隐私与合规

- 只收集运营必需信息（邮箱、用户名）；不采集无关设备信息
- 提供账号注销与数据导出（个人信息、订单历史）
- 日志中的 IP 保留 90 天，审计日志中的 IP 保留 12 个月
- 用户删除后：个人信息匿名化，订单记录保留（财务需要）但解除用户关联

## 13. 上线前安全检查清单

- [ ] 所有管理接口有权限点声明，缺省拒绝
- [ ] 订阅 token 为高熵随机，不可枚举
- [ ] Agent 签名 canonical 与面板一致（契约测试通过）
- [ ] 支付回调验签 + 幂等 + 金额校验
- [ ] 密钥全部来自环境变量，无硬编码
- [ ] 安全响应头配置
- [ ] 依赖漏洞扫描（`pnpm audit` / `govulncheck`）无高危
- [ ] 备份恢复演练通过
- [ ] 管理员默认密码已修改，2FA 已开启

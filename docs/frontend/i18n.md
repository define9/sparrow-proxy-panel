# 多语言（i18n）

## 1. 方案

`next-intl` v4，**cookie 驱动、无路由前缀**——后台 URL 稳定、便于分享；SEO 用 hreflang 解决。

| 项 | 决策 | 理由 |
|---|---|---|
| 库 | `next-intl` | App Router 原生支持，服务端与客户端共用一套 messages |
| 语言 | `zh-CN`（默认）、`en` | 面板使用者主要在国内；英文为通用 |
| 路由 | 无前缀，locale 存在 cookie `NEXT_LOCALE` | 不做 `/[locale]/admin/nodes`，链接不随语言变化 |
| 目录 | `messages/{zh-CN,en}.json` | 单文件按命名空间分组，够用不必拆分 |
| 服务端 | `i18n/request.ts` 的 `getRequestConfig` 读 cookie | 保证 SSR 与客户端一致 |
| 客户端 | 根 layout 的 `NextIntlClientProvider` | 只传当前页用到的 namespace |

不使用 `[locale]` 路由段的代价：没有语言维度的可索引 URL。本项目管理后台不需要被搜索引擎收录，接受。

## 2. 配置

```ts
// i18n/request.ts
import { getRequestConfig } from 'next-intl/server'
import { cookies } from 'next/headers'

export const locales = ['zh-CN', 'en'] as const
export type Locale = (typeof locales)[number]

export default getRequestConfig(async () => {
  const store = await cookies()
  const cookie = store.get('NEXT_LOCALE')?.value as Locale | undefined
  const locale: Locale = cookie && locales.includes(cookie) ? cookie : 'zh-CN'

  return { locale, messages: (await import(`../messages/${locale}.json`)).default }
})
```

```ts
// next.config.ts
import createNextIntlPlugin from 'next-intl/plugin'
export default createNextIntlPlugin('./i18n/request.ts')({ output: 'standalone' })
```

```tsx
// app/layout.tsx
const locale = await getLocale()

<html lang={locale} suppressHydrationWarning>
  <body>
    <NextIntlClientProvider locale={locale}>
```

## 3. 翻译文件组织

`messages/zh-CN.json` 按业务域做顶层命名空间：

```
common.*            公共：save / cancel / delete / search / empty / confirm
nav.*               导航项
auth.*              登录注册
plan.*              商品
order.*             订单（含 order.status.*）
subscription.*      订阅
node.*              节点（含 node.status.*）
user.*              用户
plugin.*            插件
log.*               日志
setting.*           设置
field.*             通用表单字段（label / placeholder / error）
error.*             错误码 → 文案
```

```json
{
  "common": { "save": "保存", "cancel": "取消", "empty": "暂无数据" },
  "nav": { "dashboard": "概览", "plans": "商品", "orders": "订单" },
  "order": { "status": { "pending": "待支付", "paid": "已支付", "cancelled": "已取消" } }
}
```

### 硬性规则

1. **禁止在组件里写死中文**，一律 `t('key')`
2. 插值用 `t('key', { count })`，复数用 ICU 语法（`{count, plural, ...}`），不要自己拼字符串
3. 状态名等枚举值**存 key 不存文案**：数据库存 `paid`，前端 `t('order.status.paid')`
4. 金额、日期不翻译，只格式化
5. 各语言的 key 集合必须一致（CI 校验）

## 4. 使用方式

```tsx
// 服务端组件
import { getTranslations } from 'next-intl/server'
const t = await getTranslations('admin.nodes')

<h1>{t('title')}</h1>
```

```tsx
// 客户端组件
'use client'
import { useTranslations } from 'next-intl'
const t = useTranslations('common')
<Button>{t('save')}</Button>
```

`NextIntlClientProvider` 默认会把整份 messages 序列化给客户端。根 layout 只传公共命名空间，页面级客户端组件用 `useMessages()` 按需取，避免 500KB 的 JSON 进首屏：

```tsx
const messages = await getMessages()   // 可按 namespace 裁剪后再传
<NextIntlClientProvider locale={locale} messages={messages}>
```

## 5. 语言切换

无路由前缀，切换 = 写 cookie + 刷新：

```tsx
'use client'
const switchLocale = (next: Locale) => {
  document.cookie = `NEXT_LOCALE=${next}; path=/; max-age=31536000; samesite=lax`
  startTransition(() => router.refresh())
}
```

- `router.refresh()` 会让 RSC 重新取 `messages`，不需要整页 reload
- 切换器放在 `NavUser` 的 DropdownMenu 子菜单里，同时展示中文名与英文名

## 6. 日期、数字、货币

统一走 `next-intl` 的 formatter，不要自己写 `Intl` 调用：

```tsx
const format = useFormatter()          // 客户端
const format = await getFormatter()    // 服务端

format.number(price, { style: 'currency', currency: 'CNY' })
format.dateTime(new Date(expireAt), { dateStyle: 'medium' })
format.number(bytes / 1024 ** 3, { maximumFractionDigits: 2 })
```

金额在接口层用**字符串**传递（`"19.90"`），前端 `format.number(Number(v), ...)`，避免浮点误差。

## 7. 后端返回的文案策略

| 类型 | 策略 |
|---|---|
| 状态枚举 | 后端返回 key（`paid`），前端翻译 |
| 错误码 | 后端返回 `code` + 默认中文 `message`；前端有 `error.{code}` 时覆盖显示 |
| 通知内容 | 数据库存模板 key + 变量，不存成品文案 |
| 系统公告 | 管理员按语言分别填写（`announcements` 存 jsonb 多语言） |

```json
{ "statusCode": 422, "code": "PLAN_OUT_OF_STOCK", "message": "商品库存不足", "data": {} }
```

```tsx
const t = useTranslations('error')
const text = t.has(code) ? t(code) : res.message
```

## 8. CI 校验

`scripts/check-i18n.ts`：

1. 遍历 `messages/*.json`，收集扁平化后的 key 集合
2. 与基准 `zh-CN` 比对：缺失 → 报错；多余 → 警告
3. 扫描 `app/` 与 `components/` 下的 `.tsx`，发现硬编码中文（排除注释与 `content`/`aria-label` 白名单）即失败
4. 校验每条消息是合法 ICU，避免运行时才炸

```bash
pnpm i18n:check    # CI 中执行，失败即阻断合并
```

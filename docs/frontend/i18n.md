# 多语言（i18n）

## 1. 方案

`@nuxtjs/i18n` v10（Nuxt 4 结构）+ Nuxt UI 内置 locale。

| 项 | 决策 | 理由 |
|---|---|---|
| 模块 | `@nuxtjs/i18n` ^10.6.0 | 官方维护，支持路由本地化、SEO、懒加载 |
| 语言 | `zh-CN`（默认）、`en`（次） | 面板主要使用者在国内；英文为通用 |
| 路由策略 | `no_prefix` | 后台系统 URL 不带语言前缀，链接稳定、便于分享；SEO 用 hreflang 解决 |
| 语言记忆 | Cookie（`useCookie`） | 用户选择优先于浏览器探测 |
| 懒加载 | `files` 数组 | 按语言分包，首屏只加载当前语言 |
| 目录 | `i18n/locales/*.json` | v10 在 Nuxt 4 下的默认结构（`restructureDir` = `i18n`） |

## 2. 目录结构

```
src/panel/
├── i18n/
│   ├── i18n.config.ts               # Vue I18n 运行时配置
│   └── locales/
│       ├── zh-CN.json
│       └── en.json
```

## 3. nuxt.config.ts

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui', '@nuxtjs/i18n'],

  i18n: {
    strategy: 'no_prefix',
    defaultLocale: 'zh-CN',
    locales: [
      { code: 'zh-CN', language: 'zh-CN', name: '简体中文', file: 'zh-CN.json' },
      { code: 'en', language: 'en', name: 'English', file: 'en.json' }
    ],
    detectBrowserLanguage: {
      useCookie: true,
      cookieKey: 'sparrow_locale',
      redirectOn: 'root',       // 仅首次访问根路径时按浏览器语言跳转
      alwaysRedirect: false
    },
    bundle: {
      optimizeTranslationDirective: false   // 保留 $t 可被静态分析
    }
  }
})
```

`i18n/i18n.config.ts`：

```ts
export default defineI18nConfig(() => ({
  legacy: false,
  fallbackLocale: 'zh-CN',
  missingWarn: true,
  fallbackWarn: false
}))
```

## 4. 与 Nuxt UI locale 的协同（关键）

安装 `@nuxtjs/i18n` 后，**Nuxt UI 会自动跟随当前 i18n locale**，并且只打包 `i18n.locales` 里匹配到的 Nuxt UI 语言包。

必须遵守：

```vue
<!-- ❌ 禁止：会把全部 50+ 语言打进 bundle -->
<script setup>
import * as locales from '@nuxt/ui/locale'
</script>

<!-- ✅ 正确：直接用当前语言，组件内部跟随 -->
<template>
  <UApp>
    <NuxtPage />
  </UApp>
</template>
```

需要覆盖 Nuxt UI 自带文案（如分页、表格、命令面板的 placeholder）时，用 `extendLocale`：

```ts
// app/app.vue
<script setup lang="ts">
import { zhCN } from '@nuxt/ui/locale'

const locale = computed(() => {
  const { locale: code } = useI18n()
  return code.value === 'en' ? en : extendLocale(zhCN, {
    messages: {
      commandPalette: { placeholder: '搜索菜单、订单、节点…' },
      table: { empty: '暂无数据' }
    }
  })
})
</script>

<template>
  <UApp :locale="locale">
    <NuxtLayout><NuxtPage /></NuxtLayout>
  </UApp>
</template>
```

> 具体导出的语言变量名以 `@nuxt/ui/locale` 实际导出为准（`zh-CN` / `zh` / `zhCN`），落地时确认一次。

## 5. 翻译文件组织

按**业务域**分文件，公共部分单独一层，用 `files` 数组做差量合并：

```ts
locales: [
  { code: 'zh-CN', name: '简体中文', files: ['common.zh-CN.json', 'zh-CN.json'] },
  { code: 'en', name: 'English', files: ['common.en.json', 'en.json'] }
]
```

加载顺序：先 `common.*`（公共词汇），再领域文件（覆盖同名词）。

### key 命名规范

```
<域>.<页面或模块>.<字段或动作>

common.*            公共：save / cancel / delete / search / empty / confirm
nav.*               导航项
auth.*              登录注册
plan.*              商品
order.*             订单（含 order.status.*）
subscription.*      订阅
node.*              节点（含 node.status.*）
user.*              用户
plugin.*            插件
log.*               日志
setting.*           设置
field.*             通用表单字段（label / placeholder / error）
```

示例（`zh-CN.json`）：

```json
{
  "common": {
    "save": "保存",
    "cancel": "取消",
    "delete": "删除",
    "search": "搜索",
    "empty": "暂无数据",
    "confirm": "确定"
  },
  "nav": {
    "dashboard": "概览",
    "plans": "商品",
    "orders": "订单",
    "subscriptions": "订阅"
  },
  "order": {
    "status": {
      "pending": "待支付",
      "paid": "已支付",
      "cancelled": "已取消",
      "expired": "已过期",
      "refunded": "已退款"
    }
  }
}
```

### 硬性规则

1. **禁止在组件里写死中文**，一律 `$t('key')` / `t('key')`
2. 插值用 `t('key', { count })`，复数用 `t('key', n)`（vue-i18n 复数规则）
3. 状态名等枚举值**存 key 不存文案**，展示时翻译（数据库存 `paid`，前端 `t('order.status.paid')`）
4. 金额、日期、时间不翻译，只格式化
5. 缺失 key 在开发环境必须报警（`missingWarn: true`），CI 校验各语言 key 集合一致

## 6. 使用方式

```vue
<script setup lang="ts">
const { t, locale, locales, setLocale } = useI18n()
</script>

<template>
  <div>{{ t('nav.orders') }}</div>
  <ULocaleSelect v-model="locale" :locales="locales" />
</template>
```

`ULocaleSelect` 是 Nuxt UI 原生语言切换器，直接用，无需自研。

服务端渲染时按 cookie / `Accept-Language` 决定 locale，保证 SSR 与客户端一致（避免水合错位）。

## 7. 日期、数字、货币

Nuxt UI 的 `UCalendar` / `UInputDate` / `UInputTime` 依据 `UApp` 的 `locale.code` 自动格式化。

业务层统一走 `app/composables/useFormatters.ts`：

```ts
export function useFormatters() {
  const { locale } = useI18n()

  const money = (v: number, currency = 'CNY') =>
    new Intl.NumberFormat(locale.value, { style: 'currency', currency }).format(v)

  const bytes = (v: number) => { /* GB/TB 换算 + Intl */ }

  const datetime = (v: string) =>
    new Intl.DateTimeFormat(locale.value, { dateStyle: 'medium', timeStyle: 'short' }).format(new Date(v))

  return { money, bytes, datetime }
}
```

## 8. SEO

`no_prefix` 策略下用 `useLocaleHead` 输出 hreflang：

```vue
<script setup lang="ts">
const head = useLocaleHead({ addDirAttribute: true, identifierAttribute: 'id' })
useHead(() => ({ htmlAttrs: head.value.htmlAttrs, link: head.value.link }))
</script>
```

每个页面的 `useSeoMeta` 里文案也走 `t()`，随语言变化。

## 9. 后端返回的文案策略

| 类型 | 策略 |
|---|---|
| 状态枚举 | 后端返回 key（`paid`），前端翻译 |
| 错误码 | 后端返回 `code` + 默认中文 `message`；前端有 key 时覆盖显示 |
| 通知内容 | 数据库存模板 key + 变量，不存成品文案（保证多语言） |
| 系统公告 | 管理员可按语言分别填写（`announcements` 加 `locale` 字段或存 jsonb 多语言） |

错误响应示例：

```json
{ "statusCode": 422, "code": "PLAN_OUT_OF_STOCK", "message": "商品库存不足", "data": {} }
```

前端：

```ts
const key = `error.${res.code}`
const text = te(key) ? t(key) : res.message
```

## 10. CI 校验

加一个脚本 `scripts/check-i18n.ts`：

1. 遍历所有 locale 文件，收集 key 集合
2. 与基准语言（zh-CN）比对：缺失 key → 报错；多余 key → 警告
3. 检查组件里是否存在硬编码中文字符串（正则扫描 `.vue` 中的中文，排除注释与 `<!-- -->`）

```bash
pnpm i18n:check    # CI 中执行，失败即阻断合并
```

## 11. 后续扩展

| 语言 | 备注 |
|---|---|
| `en` | P0 |
| `zh-TW` | P2，繁体差量文件 `zh-TW.json` 覆盖 `zh-CN.json` |
| `ja` `ko` `ru` | P2，按需 |

RTL（阿拉伯语）暂不需要，但 `useLocaleHead` 的 `dir` 属性已支持，将来加 `dir: 'rtl'` 即可，组件由 Reka UI 保证布局方向。

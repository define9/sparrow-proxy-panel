# 产品定位与功能范围

## 1. 一句话定位

一个自托管的代理服务运营面板：**Panel** 负责售卖、配额、订阅与节点管控，**Agent** 部署在节点上负责实际承载流量与上报数据。

## 2. 设计原则

1. **控制面与数据面分离**：Panel 只下发"意图"（配额、路由、节点配置），不搬运用户流量；Agent 只执行与上报，不含任何售卖逻辑。
2. **配额是唯一真理**：所有流量/设备/时间限制最终都归结为 Subscription 上的配额字段，判定逻辑集中在一处（`lib/quota.ts`），避免多处判定口径不一致。
3. **可插拔**：支付网关、节点来源、订阅渲染、通知渠道全部走插件，不硬编码进主流程。
4. **节点自治**：Panel 不可达时，Agent 必须继续按最后一次下发的配置提供服务（缓存 + 优雅降级），网络抖动不应导致代理中断。
5. **可审计**：所有写操作进审计日志；支付、鉴权、节点配置变更必须留痕。

## 3. 角色定义

| 角色 | 说明 | 入口 |
|---|---|---|
| 游客 Visitor | 浏览商品、注册 | `/register` |
| 用户 User | 已注册，购买套餐、管理订阅、查看订单 | `/dashboard` |
| 管理员 Admin | 管理商品、订单、节点、用户 | `/admin` |
| 超级管理员 SuperAdmin | 全部权限 + 插件安装 + 系统设置 | `/admin/settings` |

权限模型为 RBAC，角色与权限点在数据库中可配置（`roles` / `permissions` 表），后台可新增角色并绑定权限点。前端菜单、后端 API 校验共用同一份权限点定义（定义在 `packages/contracts`）。

| 模块 | 功能 | 优先级 |
|---|---|---|

| 首页 | 商品展示、公告、教程、节点状态概览 | P0 |
| 商品 | 商品列表/详情、价格、库存、限购 | P0 |
| 订单 | 下单、支付、订单列表、订单详情、取消、过期 | P0 |
| 订阅 | 订阅列表、订阅链接（多客户端格式）、复制二维码、流量与到期时间、IP 白名单、设备限制 | P0 |
| 流量 | 实时/周期流量图表、节点级明细 | P1 |
| 通知 | 站内信、到期提醒、流量告警（邮件/Telegram） | P1 |
| 个人设置 | 修改资料、修改密码、绑定 Telegram、切换语言/主题、API Token 管理 | P0 |
| 工单 | 用户提问与管理端回复 | P2 |

| 仪表盘 | 用户数/订单数/收入/流量/在线节点概览与趋势 | P0 |
| 商品管理 | CRUD、上下架、价格/流量/时长/倍率/设备数、排序、标签、批量导入导出 | P0 |
| 订单管理 | 列表筛选、手动完成订单、退款、订单导出 | P0 |
| 订阅管理 | 列表、编辑配额、踢下线、延长有效期、批量操作、查看订阅内容预览 | P0 |
| 节点管理 | 节点 CRUD、节点组、协议参数、证书/REALITY 配置、倍率、上下线、批量导入、同步、状态监控 | P0 |
| 节点流量 | 按节点/用户维度的流量排行与明细 | P1 |
| 用户管理 | 用户列表、搜索、角色变更、余额调整、手动延长订阅、封禁/解封、重置密码、在线状态 | P0 |
| 插件管理 | 安装/卸载/启停/配置、权限审阅、三方源、运行日志 | P1 |
| 日志 | 审计日志、登录日志、任务日志、Agent 上报事件，可检索导出 | P0 |
| 系统设置 | 站点信息、注册开关、支付配置、公告、邮件、主题、备份 | P0 |

### 4.3 Agent 端（CLI）

| 能力 | 说明 | 优先级 |
|---|---|---|
| 注册与鉴权 | 首次注册、密钥轮换、请求签名 | P0 |
| 心跳 | 在线状态、负载指标、版本、在线用户数 | P0 |
| 配置拉取 | 拉取本节点的内核配置模板 + 用户规则 | P0 |
| 流量上报 | 增量上报 per-user 流量，幂等去重 | P0 |
| 事件上报 | 内核崩溃、配置应用失败、证书过期、IP 被封 | P0 |
| 命令下发 | 重载配置、重启内核、升级内核、拉取插件、调整日志级别 | P1 |
| 自更新 | 从面板或三方源下载、签名校验、原子替换、失败回滚 | P1 |
| 内核管理 | 安装/切换 Xray / sing-box，进程守护与崩溃拉起 | P0 |
| 离线容错 | 本地缓存配置，面板不可达时继续服务 | P0 |

## 5. MVP 边界（P0，明确不做）

- 不做多租户（一个部署实例只服务一个站点运营方）
- 不做分销/返佣体系
- 不做多币种（单一 CNY）
- 不做 Node 面板与 Agent 的"双向全量配置下发"（仅下发本节点相关部分）
- 不做插件市场（仅本地安装 + 三方源拉取）
- 不做复杂 BI 报表（仅仪表盘概览 + 明细导出）

## 6. 成功指标

| 指标 | 目标 |
|---|---|
| 面板首屏 LCP | < 1.5s（境内 VPS，骨架屏 + CDN） |
| 后台列表 API P95 | < 200ms（10 万用户量级） |
| 订阅链接响应 | < 80ms（内存缓存命中） |
| Agent 心跳丢失判定 | 90s |
| 流量上报丢失率 | < 0.01%（进程内计数 + 定期落库） |
| 面板可用性 | 99.9%（Agent 侧对面板故障无感） |
